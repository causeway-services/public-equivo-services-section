## First development cycle — 2026-10-25

**Player promise:** A learning game with corpus-authored lessons, checkable actions and a useful review schedule.

**Evidence boundary:** this is a source-grounded design and production brief. Source observations are tied to the revisions below. The playtest tasks are proposed; no participants, player acceptance, retention, sales or live release are asserted.

**Observed gap:** The source has deterministic FSRS-lite scheduling, checkers, mastery projection and browser-local export/import. Historical deployment notes concern iYappy; local mastery values are not validated learning outcomes or proof of the current Equivo release.

**First question:** Can a learner explain an error, apply the concept in a new prompt and return to the right review without losing progress?

### Design and content lot

Build a content QA cycle around one complete lesson: objective, initial attempt, diagnostic feedback, varied application and later retrieval. Reuse the corpus/compiler/checker contract; inspect false-positive and false-negative grading. Make local-only progress and export/import recovery clear.

### Art, audio and interaction direction

Separate prompt, response and feedback visually; use accessible typography and restrained success/error cues. Art should clarify the concept, not compete with reading; audio is optional with text equivalence.

### Return and progression

A visible next learning purpose and spaced retrieval, not an unexplained mastery bar. Editorial review and localization are recurring service duties.

### Player study to run

1. Complete a lesson without hints, then explain an incorrect answer using the feedback.
2. Solve a materially different transfer prompt without copying the first response.
3. Export/import and return to the scheduled review; explain why it appeared.

Record the exact build/rules/save revision, date, device/input, prior experience, starting state, uncoached action and outcome, any assistance, participant explanation, counterexamples and consented quotation. A small formative study finds problems; it does not estimate market prevalence. Use the shared [Player Research method](https://github.com/coesite-operations/operations-services-section/blob/main/services/enterprise-operations-services-section/services/enterprise-media-operations-services-section/services/game-development-operations-services-section/services/player-research-operations-services-section/lib/agency/skills/observe-a-player-cycle/SKILL.md). Recruitment or external contact is a separate actual authorization, not an effect of this brief.

The producer returns a concrete continue/revise/stop decision to the same title Work. Source correctness alone does not close the player promise. Priority at this intake: **Learning/content service**.
